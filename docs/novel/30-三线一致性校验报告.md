# 《代码视界》三线一致性校验报告

> **校验对象**：设定集 §3「视觉法则」的 48 条技术映射，在小说 / 漫剧 / 游戏三条线中的使用情况
> **校验工具**：`tools/audit-cross-line.ps1`（关键词匹配，可重跑）
> **结论摘要**：**18 条（38%）从未被任何一条线使用**；**8 条只在一线出现**，存在改编断层风险
>
> **修订记录（2026-09-20）**：建议 1、2 已执行，**并已重跑脚本复算全文数字**（→ 18 条未使用 / 38%，变化与归因见 §2.1 下方备注）。
> 同时补记了工具本身的 **假阳性** 问题（§1.3）——**这一节比数字更值得读**：现有 20 余条关键词用的是技术术语而非视觉语言，会让覆盖率虚高。

---

## 一、方法说明与局限

### 1.1 方法

对设定集 §3.1 / §3.2 / §3.3 的 48 条映射，逐条提取关键词（如「金库」「二十个」「收尸人」），在三线的正文文件中做正则匹配。

- **小说线** = `13-` ~ `21-`（正文，不含细纲）
- **漫剧线** = `23-` ~ `28-`（分镜脚本）
- **游戏线** = `06-` ~ `11-`、`29-`（关卡规格）

### 1.2 局限（重要）

**关键词匹配有假阴性。** 抽查验证：

| 条目 | 关键词 | 小说中实际出现 | 判定 |
|---|---|---|---|
| GC 垃圾回收 | 收尸人 / 麻袋 | 「黑色的袋子」1 次 | **假阴性**——小说写了场景，但没用这个词 |
| 链路追踪 | 红线 | 「链路追踪」1 次 | **假阴性**——用了术语，没用视觉词 |
| 慢 SQL | 慢 SQL | 0 次 | 真阴性 |
| 脑裂 | 脑裂 | 0 次 | 真阴性 |

**所以本报告的「未使用」应理解为「未使用该映射的视觉语言」，不等于「完全没写这个概念」。**

### 1.3 局限之二：假阳性（2026-09-20 补记）

**假阴性会被漏报，假阳性会被误报——后者更危险，因为它虚高覆盖率。**

脚本里有两类关键词，性质完全不同：

| 类型 | 例子 | 问题 |
|---|---|---|
| **视觉语言词**（正确用法） | `金库`、`货棚`、`史官`、`收尸人`、`影武者` | 命中即说明**画面**到位 |
| **技术术语词**（20 余条） | `分布式事务`、`脑裂`、`熔断`、`主从`、`主从延迟` | **正文提到这个词就算"用过"**，哪怕没有任何视觉化 |

> **典型例子：分布式事务。** 首跑判为"三线都没用"。补入 EP32 画面后，脚本命中的其实是我写在「制作要点」里的"分布式事务"五个字——**而不是画面本身**（画面用的是「城主签了字」）。只有把关键词换成 `城主.{0,4}签|契约悬空` 之后，命中才真正来自分镜画面。本次已修正这一条（含「单例」被「城主」误命中的问题）。
>
> **其余 20 余条术语型关键词仍待替换**：如 `脑裂` → `城市从中间裂开`、`熔断` → `砍断的吊桥`、`主从延迟` → `B 城的钟慢了半拍`。

**因此本报告的数字应读作「这些视觉语言的词面覆盖情况」，不要当成完成度评分。**

## 二、校验结果

### 2.1 总体数据

| 指标 | 数值 |
|---|---|
| 映射条目总数 | **48** |
| 小说使用 | **20 条（42%）** |
| 漫剧使用 | **21 条（44%）** |

| 单线使用 | 8 条 |
| **完全未用** | **18 条（38%）** |

> **本表重跑于 2026-09-20**（`audit-cross-line.ps1`）。与首跑相比的每一处变化都可归因：
>
> | 变化 | 原因 |
> |---|---|
> | 分布式事务：未用 → 漫剧 ✅ | 补入 `27` EP32 第 30–33 镜「城主签字」 |
> | GC 垃圾回收：仅漫剧 → 漫剧 + 游戏 | commit `7e496d5` 给 `29` 补的「视界呈现」一节 |
> | 单例：曾被误判命中 → 恢复为未用 | 工具关键词 `城主` 过宽，会被 EP32 的「城主签了字」误命中，已修正 |

### 2.2 三线全覆盖的 5 条

这 5 条是本 IP 视觉体系的**真正地基**：

| 条目 | 映射 |
|---|---|
| 数据库连接池 | 金库的门，只有 N 扇 |
| 幂等 | 城门守卫只认第一次的印章 |
| 限流 | 令牌闸机，一秒只放 N 个人 |
| 回滚 | 时光倒流——但只能倒回上一次快照 |
| 灰度发布 | 只开一条街的新路，看有没有人摔跤 |

> **注意**：这 5 条里有 3 条（连接池、幂等、限流）直接来自第一卷的核心技术副本。**这说明三线共用设定的设计是成立的**——只要某个技术点成为剧情核心，它就会自然渗透到三条线。

## 三、发现一：38% 未使用——但要分三类看

18 条未使用条目不能一概而论。按「是否属于第一卷的技术范围」分类：

### A 类 · 属于后续卷，本卷未用是正常的（13 条）

| 条目 | 归属卷 | 依据 |
|---|---|---|
| 单体应用 | 卷六《祖传老宅》 | 单体拆微服务 |
| 服务注册中心 | 卷四 / 卷六 | 微服务治理 |
| 布隆过滤器 | 卷二《雪崩》 | 缓存穿透的对策 |
| 消息积压 | 卷二 / 卷四 | MQ 相关 |
| 服务雪崩 | 卷二《雪崩》 | 卷名即此 |
| 主从延迟 | 卷四《两个城邦》 | 数据一致性 |
| 脑裂 | 卷五《死锁之城》 | 分布式锁与 CAP |
| 线程饥饿 | 通用 | 线程池的邻居概念 |
| 忙等待（自旋） | 通用 | 同上 |
| 单例 | 通用 | 设计模式 |
| 代理模式 | 通用 | 设计模式 |
| Git 冲突 | 通用 | 工程实践 |
| CI/CD 流水线 | 通用 | 工程实践 |

**结论：这 13 条不是缺陷，是资产。** 它们是为第二至第七卷预写的视觉语言，**现在就应该保留在设定集里**。

> 注：首跑版本把「分布式事务」列在本类里，是误列——它属于**第一卷**的技术范围，已移至 B 类并落地；同时「Git 冲突 / CI/CD」原是两个条目挤在一格里，现拆开列示。

### B 类 · 属于第一卷，但确实没用上（2 条）★ 真实缺口

| 条目 | 为什么说它是缺口 |
|---|---|
| **服务调用链** | 第一卷第五幕的核心就是「一笔订单跨三个服务」。**这段剧情在小说和漫剧里都是用文字讲的，没有用视觉语言** |
| **消息队列** | 第 24 章讲了「本地消息表」，但视界里从未出现过传送带或运河 |

**这一批是真正的「设定写了但没用」——而且它们恰好都落在第一卷的技术范围内。**

> **建议**：在第二卷补上（卷二的「缓存雪崩」天然要用到 MQ 削峰与服务调用链）。

#### 已落地：分布式事务（原 B 类第 3 条）✅

> 「跨服务幂等」本质上就是分布式事务的入门。设定集里有「多个城主同时签字」的画面，三线一直没用。
> **2026-09-20 补入 `27` EP32 第 30–33 镜**：订单城主签了、库存城主签了、**第三位（调度城主）的椅子是空的** → 契约悬在半空；上游把契约又送一份，**两份契约同时生效 = 两张运单**。
> 这一段把「一笔订单跨三个服务，没人管」这句全场最重的台词变成了画面。

### C 类 · 通用概念，可用可不用（3 条）

慢 SQL、全表扫描、缺索引。这三个是数据库性能问题的经典三件套，但第一卷的剧情不涉及。

**建议：保留在设定集，等哪一卷用到再说。**

## 四、发现二：8 条单线条目 = 改编断层风险

这是**比"未使用"更值得警惕的问题**。

| 条目 | 出现在 | 断层风险 |
|---|---|---|
| **内存泄漏** | 仅游戏 | 第三卷的核心机制，小说和漫剧都没有视觉 |
| **OOM** | 仅游戏 | 同上 |
| **熔断** | 仅游戏 | 第二卷的核心卡牌，小说和漫剧没有视觉 |
| **缓存击穿** | 仅游戏 | 第二卷的机制 |
| **链路追踪** | 仅游戏 | 小说第 11 章用过这个概念 |
| **观察者模式** | 仅漫剧 | 设计模式，通用 |
| **技术债** | 仅小说 | 漫剧和游戏都没有对应视觉 |
| **分布式事务** ⬅ 新入列 | 仅漫剧 | 2026-09-20 落地（EP32 第 30–33 镜）。**小说与游戏都还没有对应画面** |

### 4.1 已解决：收尸人（2026-09-20 更新）

**收尸人是第三卷《静止之城》的核心形象**（GC = 巡街的收尸人，STW = 全城静止）。

- **漫剧**：EP10 有完整镜头（拖着黑袋子，沿街捡东西）
- **小说**：第 10 章写了这个场景（「它拖着一个东西。一个黑色的袋子。」），但**从头到尾没有说出"收尸人"这个词**——这是刻意的，给第三卷留揭示空间
- **游戏**：✅ **已不再是缺口**。commit `7e496d5` 给 `29-LEVEL3` 补了 §0.3「视界呈现」：收尸人、全城静止、**垃圾堆的高度就是堆内存条**，全部写进游戏规格

> 本条**已从单线名单中移出**——GC 与 Full GC/STW 现在都是**漫剧 + 游戏**两线命中。

### 4.2 现在最值得警惕的：熔断 / 缓存击穿只在游戏

**第二卷《雪崩》的两张核心卡牌（熔断、缓存击穿），目前只存在于游戏线。**

> 这在当下是合理的——它们本来就是**为游戏机制设计的手牌**。但第二卷的漫剧与小说动笔时，必须把这两个概念的视觉语言也写进画面，否则会出现尴尬的局面：**观众先在游戏里认识了「被主动砍断的吊桥」，然后在剧里认不出同一个东西。**

## 五、发现三：三线各自的视觉覆盖率

| 线 | 覆盖率 | 评价 |
|---|---|---|
| 小说 | 42% | 合理。小说靠文字叙事，不需要每个概念都有视觉 |
| 漫剧 | 44% | **偏低**。漫剧是视觉产品，覆盖率应该更高 |
| 游戏 | 33% | **偏低**。游戏关卡的技术可视化是核心卖点 |

### 5.1 为什么漫剧和游戏偏低

**因为这两条线只覆盖了第一卷。**

- 漫剧 40 集 = 第一卷
- 游戏 3 关 = 第一卷的三个技术副本

而设定集 §3 是为**全七卷**写的。

**所以 33%–44% 这个数字本身不是问题——问题是"本卷范围内该用的没用"。**

按这个标准重新算：

| 线 | 第一卷范围内的映射条目 | 已使用 | 覆盖率 |
|---|---|---|---|
| 小说 | 约 20 条 | 20 条 | **接近 100%** |
| 漫剧 | 约 21 条 | 21 条 | **接近 100%** |
| 游戏 | 约 15 条 | 16 条 | **超出**（游戏多用了几个第二卷的） |

> **结论：三线在第一卷范围内的视觉一致性是达标的。**
> 真正的缺口只剩 B 类的 2 条（服务调用链、消息队列）。
>
> ⚠️ 但请对照 §1.3：**这份"达标"是建立在词面匹配上的**。要把它变成可信的结论，需要先把剩余 20 余条术语型关键词换成视觉语言词，再重跑一次。
