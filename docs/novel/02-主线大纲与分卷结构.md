# 《代码视界》主线大纲与分卷结构

> 配套文档：`01-核心设定集与人物小传.md`
> **核心设计原则**：**一卷 = 一个技术副本 = 一个 Boss = 一次主角的系统性成长。**

---

## 一、全书主线：三幕结构

### 第一幕 · 看见（第一卷）

> **核心问题**：我看到的，是真的吗？

程叙入职星河科技，意外觉醒代码视界。他在无人相信的情况下，用视界解决了一次 P0 事故，却被组长沈青梧发现了异常。

**幕终转折**：沈青梧告诉他——视界是真实的，而世界上还有一群人，正在利用它毁掉一切。

---

### 第二幕 · 学会（第二卷 ~ 第六卷）

> **核心问题**：看见了，然后呢？

程叙在一次次事故中成长，从 L0 到 L3。他与静默者多次交锋，逐渐发现对方的行动纲领**并非全无道理**。同时，现实的压力（降本增效、裁员、业务扩张）不断挤压团队。

**幕中最大危机**（第五卷末）：老赵被裁。团队第一次真正分裂。
**幕终转折**（第六卷末）：程叙第一次触碰到 L4 源码层的边缘——他看见了不该看见的东西。他终于理解纪寒声为什么变了。

---

### 第三幕 · 让所有人看见（第七卷）

> **核心问题**：视界应该属于谁？

终局对决。大静默的真相揭晓。程叙面对纪寒声提出的那个无法反驳的问题：

> 「看不见的人，配管理系统吗？」

**程叙的答案**不是打倒他，而是做出一件东西——**一件能让普通人也能"看见"的东西**。

**结局落点**：
> 程叙最终没有成为最强的观者。
> 他成为了第一个**不需要视界也能看懂系统的人**——并且把这件事教给了所有人。
>
> 全书的最后一句话，是周予星说的：
> 「你负责看见，我负责让别人也看见。」

---

## 二、分卷结构总览

| 卷 | 卷名 | 核心技术副本 | Boss | 程叙视界等级 |
|---|---|---|---|---|
| 一 | **未捕获异常** | 幂等 / 分布式事务 / 日志排查 | 重复订单幽灵 | L0 → 不稳定 L3 |
| 二 | **雪崩** | 缓存穿透·击穿·雪崩 / 限流熔断降级 | 大促缓存雪崩 | 不稳定 L3 |
| 三 | **静止之城** | JVM 内存 / GC / 内存泄漏 | 全城静止（STW） | 触及稳定 L3 |
| 四 | **两个城邦** | 分库分表 / 主从延迟 / 数据一致性 | 数据不一致 | 稳定 L3 |
| 五 | **死锁之城** | 分布式锁 / 脑裂 / CAP | 脑裂 | L3（有代价） |
| 六 | **祖传老宅** | 单体拆微服务 / 技术债 / 重构 | 老宅本身 | L3 + 触碰 L4 |
| 七 | **静默** | 综合性总复盘 | 纪寒声 | 超越分层 |

## 三、分卷详纲

### 第一卷《未捕获异常》

**技术副本**：一次诡异的"重复下单"事故。同一份订单被创建了两次，两个骑手同时取货。

**Boss 形象**：**重复订单幽灵**——视界中表现为一个在城门反复盖章的影子，盖完一次又盖一次，守卫认不出哪个是真的。

**剧情推进**：

| 阶段 | 章节 | 内容 |
|---|---|---|
| 入职 | 1–6 | 程叙入职、团队初识、接下"没人愿意碰的 Bug" |
| 觉醒 | 7–12 | 首次完整开启视界，看见星河城 |
| 试错 | 13–20 | 他用视界找到根因，但因为不懂原理，看懂了却改不对。连续失败 |
| 拜师 | 21–27 | 沈青梧开始"无意地"指点他。老赵教他职场规则 |
| 爆发 | 28–36 | 第二次 P0 事故。程叙在危机中稳定在 L3，一击命中 |
| 转折 | 37–40 | 沈青梧识破他。静默者首次留下黑痕 |

**核心技术点讲解路径**（每章一个，循序渐进）：
1. 为什么"看起来正常"的系统会出问题 → 日志的价值
2. 订单为什么会重复 → 网络超时 + 重试
3. 什么是幂等 → 城门守卫与印章
4. 为什么加锁也解决不了 → 分布式环境下的锁失效
5. 最终方案 → 唯一键 + 状态机 + 消息表

**卷末高光**（第 40 章）：
> 沈青梧在楼梯间叫住程叙，说出那句让他头皮发麻的话——
> 「那个改动，救了今天早上的四千单。」
> 「我没问你为什么改。」
> 「我问的是——**你是怎么看见的。**」

**程叙成长**：学会"看得见不等于看得懂"。第一次明白：技术不是知识，是**判断力**。

---

### 第二卷《雪崩》

**技术副本**：大促前夜的缓存雪崩。缓存层大面积同时失效，所有流量瞬间打到数据库。

**Boss 形象**：**决堤的洪水**——视界中，城门口的临时货棚（缓存）同时塌陷，洪水从四面八方涌向金库的那几扇小门。

**剧情推进**：
- 程叙提出"缓存过期时间要加随机值"，被否（"小题大做"）
- 大促当晚，缓存集体过期，雪崩发生
- 数据库连接池瞬间打满，全站瘫痪
- 程叙在视界里看见洪水，喊出关键决策：**先降级，再限流，最后熔断**
- 团队按他的方案执行，系统在 8 分钟内恢复

**核心技术点**：缓存穿透 / 击穿 / 雪崩三兄弟的区别与对策、限流算法（令牌桶 vs 漏桶）、熔断器状态机、降级策略分级。

**卷末高光**：
> 程叙第一次独立指挥一场事故。他的声音在会议室里发抖，但没有一个人打断他。
> 事后老赵递给他一瓶水，说了句：
> 「小子，你今天说的话，比我八年说的都算数。」

**程叙成长**：从"能看懂"到"能决策"。技术开始变成**影响力**。

---

### 第三卷《静止之城》

**技术副本**：系统每隔几小时完全静止 3 秒。监控显示一切正常，用户投诉"页面卡死了"。所有人找不到原因。

**Boss 形象**：**收尸人**——视界中，一个拖着黑色麻袋的高大身影，沿街缓慢行走。他走到哪里，哪里的时间就停下来。

**剧情推进**：
- 诡异的间歇性卡顿持续两周，无解
- 程叙在视界里第一次看见收尸人，但不懂那是什么（他不知道 GC）
- 他开始疯狂学习 JVM 内存模型
- 发现根因：一个巨大的、被缓存了却永不过期的对象图
- 修复后，收尸人不再需要频繁出动

**核心技术点**：JVM 内存模型（堆/栈/方法区）、对象生命周期、可达性分析、分代回收、GC 日志解读、内存泄漏 vs 内存溢出、MAT/jmap 工具链。

**卷末高光**（全剧最震撼的视觉段落）：
> 收尸人停下脚步，抬起头。
>
> 他吹响了哨子。
>
> 整座城市——奔跑的人、流动的水、飘落的纸片、半空中的飞鸟——**全部静止**。
>
> 程叙站在静止的城市中央，第一次意识到：
> 「原来……**这座城一直在为我们收拾残局。**」
> 「而我们从来没看过它一眼。」

**静默者登场**：同一卷，程叙发现有人在系统里留下了**纯黑的痕迹**——不是 Bug，是**故意埋下的**。

**程叙成长**：从"看现象"到"看本质"。他开始理解系统的**生命性**。

---

### 第四卷《两个城邦》

**技术副本**：公司业务扩张，订单库分库分表。拆分后，用户看到"订单不存在"，但客服系统显示订单存在。

**Boss 形象**：**时间差**——两座一模一样的城邦并排而立，但 B 城的时钟慢了半拍。A 城已经发生的事，B 城还没听说。

**剧情推进**：
- 分库分表的工程压力
- 主从延迟导致的"读不到刚写的数据"
- 程叙提出"写后读走主库"的方案，引发架构争议
- 静默者利用主从延迟制造了一次数据错乱
- 程叙第一次与静默者正面对话（对方并未现身，只留下一段文字）

**核心技术点**：分库分表策略（范围/哈希/一致性哈希）、主从复制原理、读写分离、主从延迟的本质、最终一致性、分布式 ID 生成。

**卷末高光**：
> 程叙在两座城邦之间的吊桥上站了很久。
>
> 他忽然明白了一件事：
> 「它们不是同一座城。」
> 「但它们必须是同一座城。」
> 「这就是分布式——**你永远在说服两个不同的世界，相信同一件事。**」

**程叙成长**：视界第一次**稳定**在 L3。但代价开始显现——他的左耳出现了间歇性耳鸣。

---

### 第五卷《死锁之城》

**技术副本**：机房网络抖动，集群分裂成两个独立的部分。两个部分都认为自己才是主节点，同时对外提供服务。

**Boss 形象**：**脑裂**——一座城市从正中间裂开，变成两半。两半都在发号施令，两半都自称正统。

**剧情推进**：
- 机房故障，ZooKeeper 集群脑裂
- 分布式锁失效，同一笔退款被执行了两次
- 程叙在视界里看见城市裂开，第一次感到**无力**
- 团队通宵抢修
- 修复过程中，静默者递来一份"帮助"——一份精确到行的故障报告

**核心矛盾爆发**：
> 纪寒声说：「我帮你找到了根因。免费的。」
> 「因为我希望你看清楚——**你们这套系统，本来就是纸糊的。**」
> 「修好它，只是让它晚一点死。」

**核心技术点**：分布式锁的三种实现与各自的坑、CAP 定理的真实含义、ZooKeeper/etcd 的选举机制、脑裂的产生与防范、租约与 fencing token。

**卷末最大危机**：**老赵被裁。**
> 老赵走的那天，把四盆绿萝留在了工位上。
> 他拍了拍程叙的肩膀，说了最后一句话：
> 「小子，记住——**系统会崩，人也会。别只顾着修系统。**」

**程叙成长**：技术上的成熟 + 情感上的第一次重击。他第一次意识到：**修得好系统，救不了人。**

---

### 第六卷《祖传老宅》

**技术副本**：公司决定把运行了十一年的单体系统拆成微服务。没人敢动的那部分，交给了程叙。

**Boss 形象**：**老宅**——视界中一座爬满藤蔓的巨型建筑，违章搭建层层叠叠，墙上贴满泛黄的纸条："别碰""XXX 改于 2015.3""如果这里报错，请联系已离职的张工"。

**剧情推进**：
- 程叙走进老宅，发现里面**还有人**——那些被遗忘的业务逻辑，依然在运转
- 他发现老宅里藏着一个秘密：十一年的技术决策记录，全部由一个人维护
- 那个人的名字，是**纪寒声**
- 静默者的真正动机开始浮现

**核心技术点**：单体拆微服务的策略（绞杀者模式）、领域边界划分、数据迁移、双写与灰度切流、技术债的量化与管理。

**卷末高光**：
> 程叙在老宅最深处的房间里，找到了一面墙。
>
> 墙上密密麻麻写满了字——是十一年来，每一个被拒绝的重构提案。
>
> 最下面一行，字迹很新：
>
> 「第 18 次。我说服不了他们。」
> 「所以我决定，让他们自己**看见**。」
>
> —— 纪寒声

**程叙成长**：他第一次**同理**了反派。这是全书最重要的情感转折。

---

### 第七卷《静默》

**技术副本**：静默者的终局行动。他们要让**全世界的系统**同时静止——像三年前的大静默一样。但这一次，不会恢复。

**Boss**：**纪寒声** + **大静默真相**

**真相揭晓**（核心设定）：
> 大静默不是事故，也不是攻击。
> 那是**第一次有人触碰到源码层**——而世界本身，为了修复那一次触碰，暂停了 1.7 秒。
>
> 纪寒声当时就在那个房间里。他和沈青梧一起，看见了 L4 的边缘。
>
> 他看见的，不是"世界的源代码"。
> 他看见的是——**没有人真正拥有这座城。所有人都在替别人保管它。**
>
> 从那一刻起，他决定：**既然没人拥有，那就由看得见的人来拥有。**

**终局对决**：
- 程叙 vs 纪寒声
- 不是打斗，是**两个观者在同一座城市的视界里，做不同的选择**
- 纪寒声要"停止"整座城市，让它归零
- 程叙要"打开"整座城市，让所有人看见

**程叙的解法**（全书主题的落点）：
> 他没有试图打败纪寒声。
>
> 他做了一件纪寒声从没想过的事——
>
> **他把视界"投影"了出来。**
>
> 用一整面墙的屏幕，用最笨的方法，把星河城的真形，一帧一帧地渲染给所有不懂技术的人看。
>
> 产品经理看见了。运营看见了。韩立冬看见了。
>
> 韩立冬站在那面墙前面，站了很久。
>
> 然后他说了一句话：
> 「……原来你们一直在这种地方工作。」

**结局**：
- 纪寒声没有被打倒。他站在那面墙前面，看了很久，然后转身离开。
- 他没有被抓，也没有投降。他只是……**第一次被看见了**。
- 最后一章，程叙回到工位，继续写他的 CRUD。
- 老赵的绿萝，活了。

**最后一句话**（周予星）：
> 「你负责看见，我负责让别人也看见。」

## 四、改编适配性说明

> 本章节为"极易做成漫剧和游戏"这一核心诉求提供直接落点。

### 4.1 漫剧适配

**每集结构**（90–120 秒）：本作天然适配竖屏漫剧的节奏。

```
0–15s   日常钩子：职场真实吐槽，低成本，扁平色
15–30s  危机出现：一句台词引爆，"线上炸了"
30–75s  视界开启：招牌仪式 + 全特效段落（长镜头）
75–105s 解决过程：技术可视化，爽点释放
105–120s 结尾钩子：一句话反转，逼出下一集
```

**成本结构优势**：日常段落（省成本）与视界段落（高燃）交替，比例约 **6:4**。这个比例让作品既有电影级的视觉爆点，又不至于烧穿预算。

**招牌镜头复用清单**（每集必用其一，形成系列辨识度）：
1. 三下敲击 → 世界静音 → 瞳孔炸开数据流 → 线框卸载 → 城市升起 → `SYSTEM ONLINE`
2. 全城静止（STW）：声音被抽干，绝对死寂
3. 洪水决堤（缓存雪崩）：多线并行，同时冲垮
4. 城市从中间裂开（脑裂）

**弹幕收割点**：老赵的金句库。每一句都是天然的弹幕爆点。

---

### 4.2 游戏适配

**类型定位**：**剧情 AVG + 战术决策战斗**（非数值碾压型）

**核心玩法循环**：
```
剧情推进 → 事故发生 → 进入视界（情报阶段）→ 选择技术方案（决策阶段）→ 执行与承受后果 → 复盘成长
```

**战斗系统的独特性**（这是本作最值钱的设计）：

> **你不"打死"敌人。你要在有限步数内，把系统可用性维持在 99.9% 以上。**

| 要素 | 设计 |
|---|---|
| **敌人** | 慢 SQL、缓存雪崩、死锁、OOM、脑裂……每一次都是一个**有明确规则的系统故障** |
| **手牌** | 技术手段：限流、熔断、降级、扩容、回滚、灰度、加索引、加缓存…… |
| **资源** | 时间、机器配额、团队精力（有限的"决策点"） |
| **胜负条件** | 不是消灭敌人，是**可用性不低于阈值**且**不触发不可逆损失**（数据丢失 = 永久失败） |
| **评分** | 参考真实工程指标：MTTR（平均恢复时间）、影响用户数、是否根因解决 or 只是压住 |

**关键设计**：每一步技术选择都必须**有代价**。
- 加缓存 → 快，但引入一致性风险
- 加锁 → 一致，但可能死锁
- 限流 → 保住系统，但用户投诉
- 回滚 → 快速止血，但问题还在

**没有完美解，只有权衡。** 这才是真实工程，也才是好游戏。

**养成系统**：技能树 = **真实技术栈学习路径**
```
Java 基础 → 集合与并发 → JVM → 网络与 IO → 数据库与索引
→ 缓存与消息队列 → 分布式与一致性 → 系统架构
```
玩家点满一条技能树时，**真的理解了对应技术**。这是本作"寓教于乐"的终极形态。

**关卡 = 章节 = 事故副本**。每一卷对应一个大型副本，每一章对应一个关卡。

**可收集要素**：队友角色（老赵、周予星、孙野、沈青梧），每人有独特的"被动能力"：
- 老赵：**业务透视**——提前一回合看到故障的业务影响范围
- 周予星：**快速原型**——把任意方案的成本减半
- 孙野：**监控预感**——有概率提前一回合获得预警
