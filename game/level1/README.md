# LEVEL 1《幽灵订单》· 可玩灰盒原型

> `05-游戏原型设计文档` §8.2 要求的 MVP 灰盒：**纯文字 + 图标、只做 LEVEL 1、不做美术资产**。
> 本目录是三线里第一件「能跑起来的东西」。
>
> 实现依据：`06-LEVEL1-实现规格`（逻辑）、`07-LEVEL1-文案全集`（文本）、`08-LEVEL1-数值表`（数值）

---

## 怎么玩

**双击 `index.html`** 就能玩。没有构建步骤，没有依赖，不需要起服务器。

用键盘鼠标：
- 右侧「可执行操作」点一张卡 = 一个回合
- 右侧「观察一分钟」= 什么都不做，等一分钟
- 左栏是三条资源轴与已掌握线索，中栏是处置记录
- 顶栏「明/暗」切换主题（默认深色，因为这是运维大盘）

一次通关大约 5–10 分钟。**建议第一遍凭直觉玩**——本作最重要的教学时刻（`重启服务` 那个陷阱）设计上就是给玩家自己踩的，别提前看攻略。

## 目录结构

```
game/level1/
├─ index.html            界面骨架（脚本按 data → texts → engine → ui 顺序装载）
├─ css/style.css         视觉：星河科技运维大盘
├─ js/
│   ├─ data.js           数据层：相位表 / 证据表 / 16 张卡牌 / 全局常量
│   ├─ texts.js          文案层：所有玩家可见文本（按 logKey 取用）
│   ├─ engine.js         逻辑层：状态机 + 分段积分 + 证据链 + 胜负评级（无 DOM 依赖）
│   └─ ui.js             渲染层：把状态画出来、把点击翻译成动作
└─ tests/
    ├─ run.js            逻辑层验收：§9 十条 + §10 四条参考路径 + 规格护栏（90 项）
    └─ ui-smoke.js       界面层冒烟：主链路 / 结算 / 超频确认 / 失败路径（51 项）
```

分层是刻意的：**engine.js 不碰 DOM**，所以它能被 Node 直接 require 来做自动化验收。换界面不用动逻辑，改数值不用动界面。

### 跑校验

```bash
node game/level1/tests/run.js        # 90 项，逻辑
node game/level1/tests/ui-smoke.js   # 51 项，界面
```

改任何数值（相位倍率、卡牌成本、Impact 阈值）之后都应该重跑 —— 这是本工作区
「改数值必须重跑校验」那条惯例在游戏线上的对应物。

### 音效为什么没做

`05` §8.2 只要求 3 个音效（卡牌打出 / 故障复发 / 通关）。原型阶段我没引入音频文件：
一是会往仓库里塞二进制资产，二是音频格式与浏览器自动播放策略会带来额外变量，
而灰盒要验证的是**「诊断 → 权衡 → 承担后果」好不好玩**，不是听觉。

代码里留了位置：`ui.js` 的 `afterAction()` 是播报时机，`T.banner` 是正反馈文案。
要加只需引 mp3 + 在三个点各调一次 `new Audio(...).play()`。

## 与规格的偏差（5 处，全部因为规格内部算不通）

实现过程中逐条跑验收，撞出 5 处**规格自身矛盾**。每一处我都选了「保住带具体数字的产物最多」的那一边，
并把判定依据写进了代码注释。这里集中登记。

### 偏差 1 · 团队精力初始值 5 → **8**

`06` §1.1 写 `teamStamina 初值 5 / max 5`。但 §10 路径 A（标准解）需要：
看监控 0 + 看日志 0 + 链路追踪 1 + 同步进展 1 + 查看上游调用 1 + 限流 1 + 发版 3 = **7 点**。

**按 5 点实现的路径 A 物理不可达**，与 §9 验收第 2 条（"正解路径打出后 Impact≈43.95，评级 A"）直接冲突。
判定为笔误：详细设计时把回精力的 `拉人进来` 从卡表里删了（§0.1 记了这次删减），却没同步上调精力上限。

取 8，保留 1 点容错。`data.js` 的 `CONFIG.staminaMax` 有完整注释。

### 偏差 2 · 强制接管事件**不改数值**

`06` §6.2 写强制接管时「同时执行 `onRestart()` 逻辑」——而 `onRestart()` 会把 Impact 归零、phaseBonus +0.5。
若照做，以下**四处带具体数字的产物全部失效**：

| 产物 | 内容 |
|---|---|
| §3.3 被动失败曲线 | 15 分 → 64.50 |
| §9-1 验收项 | 不做操作，15 分钟 Impact ≈ 64.50 |
| §10 路径 D | 逐回合表，15 分 → 64.50 |
| `07` §5.2 F 级结算样例 | 15 分 → 64.5 / 2064 人 |

而且从设计上说不通：**Impact 是本作的失败线，一个"惩罚事件"把它归零等于发奖励。**
`07` §4.2 的原话已经给出了正确语义：**「它不直接扣分，但它毁掉了证据链。」**

→ 本实现：强制接管只清证据、置 `evidenceLost`，**不动 Impact / phaseBonus / restartCount**。

### 偏差 3 · 视界前置改用「曾经看到过」的线索

`06` §0.1 把视界前置条件定为「需已有 ≥2 条证据」，`§4.3` 又规定重启清空全部证据。
两者叠加的后果是：**重启后视界永远不可用**，而 §4.3 自己写着「重启封死了所有常规诊断路径，
**但没封死视界**」——这是它声称的「本关最重要的一条平衡规则」。§9 验收第 5 条也要求重启后能靠视界通关。

→ 拆成两个概念：`evidence`（现场证据，重启清空）与 `evidenceEver`（曾经看到过的线索，永不回退）。
视界前置读后者。语义上也更对：**视界是程叙自己的能力，日志被重启冲掉了，他看过的东西不会。**

**连带影响**：`06` §10 路径 C 的卡片顺序（第 2 回合重启、第 3 回合才看日志）在这个设计下走不通——
重启后手上只剩 1 条（看监控给的 E2），永远够不到 ≥2。测试里把这个失败**原样断言下来当护栏**，
再用修正顺序 **C′** 验证设计意图：

| 回合 | 行动 | 时间 | Impact |
|---|---|---|---|
| 1 | 看监控大盘 | 0 | 0 |
| 2 | 看日志 | 1 | 3.00 |
| 3 | **重启服务** | 2 | 0（`phaseBonus=0.5`） |
| 4 | 限流 | 3 | 4.50 |
| 5 | **开启视界** | 3 | 4.50 |
| 6 | 改代码 + 发版 | 11 | **26.85** |

→ **评级 B（未封顶前本应 A）**，与 §10-C 的结论完全一致，只有 Impact 数值不同（26.85 vs 31.35，差在日志的位置）。

### 偏差 4 · 「不用同步进展必然超时」在算术上不成立

`06` §0.2（标注"实现时不可偏离"）与 §9-7 都断言：正解路径总耗时 15 分钟，
**不用 `同步进展` 就一定超时**。

但 §10-A 那 15 分钟里含 `同步进展` 自身那 1 分钟。扣掉它只剩 **14** —— 不用同步进展也能极限通关。

**这条改不动**：任何卡牌成本 +1 都会同时推翻 §10-A 的 43.95。所以不改数值，改认知——
正确的结论是「**没有任何容错余量**」：同样路线中途只要多花 1 分钟（比如顺手比对了一下变更），
立刻超时。测试里两个断言并排放着，把这个边界钉死。

顺带：本实现按 §8「让后果发生」的意图，把「发版完成但已过错」判为**输**（`timeElapsed > timeLimit`），
同时保留 §2.1 的边界保护（`t == limit` 卡点完成算**赢**）。

### 偏差 5 · §3.3 的破线时刻 21.2 → **20.933**

按 §3.3 表自己的数值推：20 分时 93.00，P4 强度 7.50/分 → 破线时刻 = 20 + 7 ÷ 7.5 = **20.933 分**。
原表 21.2 是笔误（差 0.27 分钟）。

## 两个统计口径（`07` 的样例数字反推出来的）

结算界面的「有效操作」与「浪费的时间」在规格里没有精确定义，是拿 `07` §5.2 的三份样例
（S 级 4/5、A 级 5/7、B 级 4/6，浪费 0/0/1 分钟）反推出来的口径，三条全部吻合：

| 指标 | 口径 |
|---|---|
| **有效操作** | 该操作**产生了新线索**，或新确认了根因，或完成了根治。（缓解与沟通类不计） |
| **浪费的时间** | 只统计打在**纯陷阱卡**上的时间：`扩容` / `加缓存` / `加索引` / `重启服务` |

> 「浪费的时间」不含 `翻历史记录`——它的规格标记是 `effective: true`（确实产出了 E7），
> 只是对通关毫无帮助。这一条 `07` 的 F 级复盘正文有写，所以不重复计入浪费。
